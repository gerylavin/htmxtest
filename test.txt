By default, SQLModel (which is built on SQLAlchemy) uses eager loading for relationships, meaning it fetches related models automatically or requires explicit joins. To implement lazy loading—where related data is only fetched from the database the moment you access the property—you need to configure the Relationship function using SQLAlchemy's lazy="select" or lazy="dynamic" arguments.
Here is how to set up lazy loading in SQLModel and safely use it within a FastAPI application.
------------------------------
## 1. Configure the SQLModel Relationship
To enable lazy loading, pass the sa_relationship_kwargs argument to SQLModel's Relationship function.

from typing import List, Optionalfrom sqlmodel import Field, Relationship, SQLModel
class Team(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str
    
    # 💡 sa_relationship_kwargs {"lazy": "select"} enables lazy loading
    heroes: List["Hero"] = Relationship(
        back_populates="team", 
        sa_relationship_kwargs={"lazy": "select"}
    )
class Hero(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str
    team_id: Optional[int] = Field(default=None, foreign_key="team.id")
    
    team: Optional[Team] = Relationship(
        back_populates="heroes", 
        sa_relationship_kwargs={"lazy": "select"}
    )

## 2. The FastAPI Warning: The "DetachedInstanceError"
Lazy loading requires an active database session. If you try to access a lazy-loaded relationship after the FastAPI response has started serializing, or after the session closes, SQLAlchemy will throw a DetachedInstanceError.
## ❌ The Wrong Way (Will Crash)
If your FastAPI endpoint returns a Pydantic/SQLModel schema that includes the relationship, FastAPI will try to read team.heroes after the Session block has closed.

@app.get("/teams/{team_id}", response_model=TeamWithHeroes)def get_team(team_id: int):
    with Session(engine) as session:
        team = session.get(Team, team_id)
        return team  # ❌ Session closes here!
        
    # FastAPI tries to serialize 'heroes' here, but the session is dead.
    # Result: DetachedInstanceError

## The Right Way (Option A): Access inside the Session
Access or trigger the lazy load while the database session is still open.

@app.get("/teams/{team_id}")def get_team(team_id: int):
    with Session(engine) as session:
        team = session.get(Team, team_id)
        
        # 💡 Accessing the property triggers the SQL query while session is active
        hero_list = team.heroes 
        
        return {
            "team_name": team.name,
            "heroes": [hero.name for hero in hero_list]
        }

## ⚡ The Right Way (Option B): Use FastAPI Depends Session
If you use a FastAPI dependency to manage your session lifecycle, the session stays open until the request is fully serialized and sent to the client.

from fastapi import Dependsfrom sqlmodel import Session
# Session generator dependencydef get_session():
    with Session(engine) as session:
        yield session

@app.get("/teams/{team_id}", response_model=TeamWithHeroes)def get_team(team_id: int, session: Session = Depends(get_session)):
    team = session.get(Team, team_id)
    #  Safe! The session remains open while FastAPI serializes TeamWithHeroes
    return team 

------------------------------
## Eager vs. Lazy Loading in SQLModel

| Strategy | sa_relationship_kwargs | Best For | Behavior |
|---|---|---|---|
| Lazy | {"lazy": "select"} | Large collections or properties rarely accessed. | Emits a new SELECT query the moment you read the attribute. |
| Eager (Joined) | {"lazy": "joined"} | Always-needed properties, 1-to-1 relationships. | Joins the tables instantly using a single LEFT OUTER JOIN SQL query. |
| Eager (Selectin) | {"lazy": "selectin"} | 1-to-many collections needed immediately. | Emits a second, optimized SELECT ... IN query immediately for child rows. |
